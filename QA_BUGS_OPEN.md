## Раунд 8 — P2

**[P2] «Сегодня» на прошлом дне: вес пустой для дат старше последних 30 взвешиваний**
Файл: `web/app/(app)/dashboard/page.tsx:118, 302`
`dayWeight` ищется в `getRecentActualWeights(30)` (последние 30 записей), иначе берётся `daily_log.weight_kg`. Старый экран «Вес» писал только в `weight_entry`. В проде у одной пользовательницы 65 дат, где вес есть только в `weight_entry` и они старше последних 30 записей: на «Сегодня?date=…» поле пустое, на «Весе» значение есть. Ещё на 2 датах `daily_log.weight_kg` ≠ `weight_entry.actual_kg`: за пределами окна «Сегодня» покажет устаревшее значение.
Предложение: читать `weight_entry` за `dayKey` отдельным запросом и предпочитать его. Расхождения можно разовым скриптом свести к `weight_entry` (после согласования).

**[P2] Прошлый день: список препаратов текущий — архивную отметку или отметку старой дозы не снять, а снятие «новой дозы» не убирает приём из счёта**
Файлы: `web/app/(app)/dashboard/page.tsx:111`, `today-day.tsx:111-122`, `checkin/actions.ts:333-339`
`getMeds()` не отдаёт архивные препараты и закрытые версии доз. Сценарий: Суматриптан 50 → «доза» → 100 мг; открыть день до смены. Галочка стоит (совпал `habit_key`), снимаем → `setMedTaken(newId, false)` удаляет `habit_key`, но старый id остаётся в `meds_taken`. Счётчик МИГБ и тепловая карта (матч по id) продолжают считать приём. Архивный препарат на прошлом дне вообще не виден.
Предложение: для прошлой даты показывать препараты, активные в эту дату, плюс всё, что уже отмечено в строке дня. При снятии отметки удалять из `meds_taken` все id с тем же `habit_key`.

**[P2] Гонка read-modify-write на `daily_log` (`TrainingQuickAdd`/`saveWorkout` вне очереди) — реальный риск низкий**
Файлы: `web/app/(app)/training/actions.ts:45-71`, `web/app/(app)/checkin/training-quick-add.tsx:40-57`, `web/components/save-queue.tsx`

Возможна только при двух вкладках или устройствах. Худший случай: `patchDay` перезаписывает `habits_done` и теряет «Спорт»/«Бег», которые больше никто не читает. Либо `saveWorkout` (column-only update) теряет `habit_key` препарата, но тепловая карта всё равно засчитает приём по id из `meds_taken`. ## Раунд 8 — проверено и подтверждено НЕ багом

- **Изоляция в новом коде.** `setMedTaken` проверяет владение `medId` через `byUser`. `saveMigraineDetails`/`saveDayNumber` идут через `patchDay`: чтение `byUser`, запись с `app_user_id = uid`. `saveTrackedModules`/`saveModules` пишут через `.eq("id", uid)` (без пользователя `getUid` бросает исключение). `getMigraineMedStatsByMonth`, `getMigreDiaryMonth`, `getCycleHistory` фильтруют `byUser`. `updateCalendarEvent` — `byUser` + `eq id`, id приходит из серверных пропсов. `deleteMigraineTrigger` — `byUser`.
- **Прод.** 0 строк с `app_user_id IS NULL` в `daily_log`, `weight_entry`, `medication`, `migraine_event`, `cycle_start`, `workout_log`, `sport_type`; созданных или обновлённых после 2026-10-20 — тоже 0. В `calendar_event` одна старая (см. P1). Колонки миграции 060 на месте, у всех 5 аккаунтов включены все три раздела.
- **`?date=`.** Будущая дата → сегодня. Плейсхолдер веса только для сегодня. Приступ, препараты, вес и ккал пишутся в `dayKey`. `TodayDay` и `PeriodStartButton` с `key={dayKey}`. День цикла считается от стартов ≤ `dayKey`. «Месячные начались» на прошлом дне → `addCycleStart(dayKey)`.
- **«Вес».** Ккал вчера → `kcalDay = yesterday`. `saveWeight` синхронизирует `daily_log.weight_kg` column-only update. Upsert `weight_entry` не трогает `plan_kg`.
- **`habits_done`.** Ни одно новое действие не затирает отметки: `setMedTaken` меняет только свой ключ; `saveMigraineDetails`/`saveDayNumber`/`quickLogMigraine` переносят `habits_done` из прочитанной строки; `saveWorkout`/`saveCalories`/`saveWeight` — column-only. Тепловая карта матчит по id ИЛИ `habit_key`.
- **МИГБ.** Для одного месяца `getMigraineMedStatsByMonth` эквивалентна старой логике: legacy triptan ∪ high-risk ids; nsaid; unclassified. `total` = |highRisk ∪ nsaid|. `ymAdd` верно переходит декабрь → январь. `fromYM` = 12 месяцев включая текущий (проверено для ноября, декабря и января). «Сегодня», плитки дневника и шторка берут одну функцию. `medLoad` учитывает смешанный приём только при обеих группах. Янтарный с 70 % ориентира — везде.
- **Удалённые экраны.** Ни одной ссылки или импорта на `/habits`, `/balance`, `/medical`. Все `revalidatePath` указывают на существующие маршруты. `/checkin?date=` → `/dashboard?date=`. Proxy matcher чистый. Онбординг: цикл → модули → (вес).
- **Модули.** Последний раздел не выключить ни в UI (`disabled`), ни на сервере. `BottomNav` фильтрует вкладки. На «Сегодня» плитки, приступ, тренировка, вес/ккал и расписание недели — под флагами.
- **Клиентский бандл.** `lib/seed-data` в него не попадает: `lib/data.ts` под `server-only`, клиентские компоненты импортируют только типы.
- **Тексты по ревью Елены.** «триптаны и др.»; `--caution` янтарный, не `--warn`; «Профилактика и витамины не считаются»; `medNote` в шторке только у ориентира и с «Это не запрет…»; ссылка `#urgent` есть в шапке «Мигрени» и в шторке, якорь `id="urgent"` существует.
- **Сборка и вёрстка.** `tsc --noEmit` и `next build` — чисто. На 320 px без горизонтального переполнения: «Сегодня» (вне режима правки), шторка приступа, дневник, график, легенда, карточка вес/ккал, «Что отслеживаю».

**[P2 — намеренно не меняем] `MIGREBOT_MED_PATTERNS` — эвристика по regex может давать ложные срабатывания**
Файл: `web/lib/migrebot-meds.ts`

Решение: не менять, пока не появятся жалобы на конкретные ложные срабатывания. При появлении — рассмотреть явное подтверждение перед авто-регистрацией вместо тихого создания.

**[P2 — намеренно не меняем] `buildDayRange`/`addDays` — потенциально тяжёлый цикл при расширении диапазона**
Файл: `web/app/(app)/checkin/meds/med-calendar.tsx`
Окно всё ещё 3 месяца (`/checkin/meds/page.tsx`'s `addMonths(endISO, -3)`) — ~90 итераций, не проблема. При расширении до года будет 365 итераций с созданием `Date` — не критично, но иметь в виду.
Решение: не трогать, пока не меняется сам диапазон.
